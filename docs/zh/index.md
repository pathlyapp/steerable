<h2 class="sf-section" id="quickstart">方便集成</h2>

<p class="sf-lede" markdown>
只引入你需要的那一层——Python 后端、React 对话界面或桌面 Sidecar；纯 UI 预览运行 <code>pnpm shell:dev</code>。
</p>

<div class="sf-tabs" markdown>

=== "Python 智能体后端"

    ```bash
    uv add steerable-agent-protocol steerable-agent-harness steerable-agent-runtime
    ```

    ```python
    from steerable_agent_runtime import ToolRouter, tool
    from steerable_agent_protocol import ToolCall

    router = ToolRouter()

    @tool(router=router, description="按路径读取文件")
    async def read_file(path: str) -> dict:
        return {"path": path, "content": open(path).read()}

    result = await router.dispatch(
        ToolCall(id="c1", name="read_file", arguments={"path": "README.md"})
    )
    # result.success、result.data、result.error 均有完整类型约束
    ```

=== "React 对话界面"

    ```bash
    pnpm add @steerable/agent-protocol @steerable/agent-ui
    ```

    ```tsx
    import { ChatPanel, useChatStream } from '@steerable/agent-ui';

    export function Chat() {
      const { messages, send, isStreaming } = useChatStream({
        endpoint: '/api/chats/123/send',
      });
      return <ChatPanel messages={messages} onSubmit={send} isStreaming={isStreaming} />;
    }
    ```

=== "桌面应用 + 本地 Sidecar"

    ```bash
    # 将 Sidecar 二进制放入 resources/python-runtime/<platform>/
    pnpm add @steerable/agent-runtime
    ```

    ```ts
    import { AgentRuntime } from '@steerable/agent-runtime';

    const runtime = new AgentRuntime({ sidecarPath });
    await runtime.start();   // 启动进程并完成 lifecycle.ready 握手

    const stream = await runtime.chatStream({
      provider: 'openai_compat',
      model: 'glm-5.3-flash',
      baseUrl: process.env.GATEWAY_BASE_URL!,
      apiKey: process.env.GATEWAY_API_KEY!,
      messages: [{ role: 'user', content: 'hi' }],
    });
    for await (const event of stream.events) { /* 强类型 SSEEvent 流 */ }
    ```

<h2 class="sf-section" id="why">核心机制</h2>

<p class="sf-lede" markdown>
专为高性价比与本地模型打造——从工具解析、事实核查到 OS 沙箱逐层兜底。
</p>

<div class="sf-pillars" markdown>
<div class="sf-pillar" id="pillar-1" markdown>
<span class="sf-pillar-kicker">01 · 更少幻觉</span>
### 事实核查与自动纠错
拦截无依据结论与空头支票，自动解析并重试纯文本畸形工具调用。
</div>
<div class="sf-pillar" id="pillar-2" markdown>
<span class="sf-pillar-kicker">02 · 简单易用</span>
### 半天即可上手
无图编排 DSL。`@tool` 装饰普通函数，Harness 零 I/O，单份 Schema 生成双端类型。
</div>
<div class="sf-pillar" id="pillar-3" markdown>
<span class="sf-pillar-kicker">03 · 开箱即用</span>
### 默认闭环沙箱
内置 Seatbelt / bwrap / Windows 沙箱、61 条命令规则与白名单代理。免 Key [在线演示](../demo/)。
</div>
<div class="sf-pillar" id="pillar-4" markdown>
<span class="sf-pillar-kicker">04 · 分层可拆</span>
### 按层按需取用
5 层 15 个独立包，严格单向依赖。可只引入协议、UI 或 Sidecar。
</div>
</div>

<h2 class="sf-section" id="compare">框架对比</h2>

<p class="sf-lede" markdown>
不止看通过率——从部署形态、事件流、沙箱边界与模型质量层横向对比主流方案：
</p>

<div class="sf-compare-wrap" markdown>

| 对比维度 | Steerable | OpenAI Codex | DeepSeek Harness | LangGraph | OpenAI Agents SDK | Claude Code / Agent SDK |
| -------- | --------- | ------------ | ---------------- | --------- | ----------------- | ----------------------- |
| **定位与交付** | **5 层按需拆装**：签名桌面 Sidecar + FastAPI 服务端 + 14 卡 React UI，一套协议打通 | 闭环编程产品家族（CLI / IDE / 云端），非可嵌入 UI/SDK 栈 | TS 插件化底座（Cordis），偏 CLI / Web 宿主，无独立桌面 Sidecar | 仅状态图编排库，无内置 UI、沙箱或端侧运行时 | 仅服务端轻量编排，无桌面 Sidecar 或前端 UI | 闭源整包 CLI + SDK，无法拆层嵌入自有架构 |
| **便宜 / 本地小模型** | **原生容错**：自动解析纯文本畸形调用 + 事实核查 + 完成否决（Flash 实测 **79.0%**） | 默认模型稳定输出标准 `tool_calls` | 默认模型输出标准 `tool_calls` | 无内置恢复，需业务方自建循环与校验 | 面向旗舰前沿模型设计 | 面向 Claude 前沿模型设计 |
| **模型与厂商绑定** | **零绑定**：OpenAI 兼容（Ollama/vLLM）/ Responses / Anthropic / Gemini 四协议切换 | 以 Responses 协议与 OpenAI 生态为核心 | 支持多模型（侧重 DeepSeek / 标准接口） | 支持多模型（由业务代码接 SDK） | 强绑定 OpenAI（跨厂商需借助 LiteLLM 适配） | **仅支持 Anthropic 模型**（经 8 个后端路由） |
| **默认沙箱与出网** | **默认 Fail-closed**：Seatbelt / bwrap / Windows + 61 条规则 + 按域名 CONNECT 白名单代理 | 平台沙箱 + 审批策略 + 托管网络代理 | `sandbox.confine`（Fail-closed） | **无内置沙箱**（需自建 Docker / 云沙箱） | 依赖 Docker 或托管沙箱（本地 Unix 无 Linux 隔离） | CLI 默认 **Fail-open**（缺沙箱仅警告仍继续执行） |
| **TS + Python 契约** | **单份 JSON Schema 生成** TS/Zod + Pydantic，15 包锁步发布 + 黄金一致性测试 | 生成 TS 类型，双语言各自维护 SDK | TS 为主，Python SDK 通过 CLI/RPC 桥接 | Py / JS 两套独立库，无单源跨语言 Schema | Py / TS 两套独立库，无跨语言代码生成 | 仅发布 TS 类型定义（`sdk-tools.d.ts`） |
| **取舍与现状** | `CoreLoop` 引擎为闭源二进制包；生态仍处早期（`0.12.x`） | 生产体量极大，但难以单独拆分其中一层嵌入 | 开源可自由扩展，仍处公开预发布（`0.2.x`） | 生态最成熟，但循环护栏与界面全部自建 | 上手快，但缺乏端侧与跨层能力 | 能力完备，但全闭源且锁死 Anthropic 模型 |

</div>
