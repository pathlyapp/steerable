# 目标跟踪（Goal）

用法：`/goal <目标>`。

- 目标为空时显示 `Usage: /goal <目标>`。
- Goal 没有时间、token 或回合上限。以 `30m`、`2h` 等时限开头时，明确说明暂不支持时限，然后去掉时限创建目标。
- “每隔 / 每天 / every”是重复工作，应使用 `/loop`。

## 启动

1. 用一句话重述完整目标，并保留用户要求的每个交付物与验收证据。
2. 恰好调用一次 `create_goal`。不要自行创建 goal 文件；不要用 `todo_write` 代替 goal。
3. 创建失败时明确说明目标没有启动，不要重试创建。
4. 创建成功后，本回合立即完成第一个具体工作单元；不能只规划或只创建目标就结束。

## 持续执行

- 目标跨回合存在。保持原目标完整，不得为了本回合能收尾而缩小范围或降低验收标准。
- 以当前工作区、命令输出、测试结果与外部状态为准；旧对话只用于定位。
- 多步骤工作可以用 `todo_write` 显示进度，但 todo 只是可见计划，不是 goal 状态，也不能替代实际工作。

## 完成核对

决定完成前先假定“尚未完成”：

- 从目标和引用的文件、方案、issue 中逐条导出要求。
- 为每项要求找到范围匹配的当前证据；缺失、间接或不确定的证据都视为未完成。
- 意图、部分进展、旧输出和“没发现问题”不能证明完成。

只有全部要求都有直接证据且没有剩余工作时，才调用 `update_goal`，action 为 `complete`。用户明确要求暂停时才用 `pause`。同一真实阻塞连续出现至少三个目标回合、且没有任何安全的下一步时，才用 `blocked` 并给出具体原因。
